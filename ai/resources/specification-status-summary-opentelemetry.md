# Specification Status Summary | OpenTelemetry

## Summary

- **Signal Architecture**: OpenTelemetry (OTel) is structured around signals (e.g., tracing, metrics, baggage, logging) built on shared context propagation, with each signal comprising APIs, SDKs, OTLP, and a Collector; contrib components provide extensibility via semantic conventions.

- **Component Lifecycle**: OTel components follow a staged lifecycle (Draft → Experimental → Stable → Deprecated → Removed), with Stable components offering backward compatibility and long-term support per [versioning policies](https://opentelemetry.io/docs/specs/otel/versioning-and-stability/).

- **Signal Status (2025-10-19)**:
  - **Tracing/Metrics/Baggage/Logging**: APIs/SDKs/OTLP stable (metrics SDK mixed; baggage lacks OTLP).
  - **Profiles**: OTLP in development.
  - **Collector**: Status mirrors OTLP for all signals.
