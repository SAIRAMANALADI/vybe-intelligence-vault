# GitHub - golang/proposal: Go Project Design Documents · GitHub

## Summary

- **Proposal Workflow**: Significant changes to Go (language, libraries, tools, or `go` command) require a structured proposal process: initial issue filing → triage (accept/decline/design doc) → optional design doc → final decision. Language changes follow a [Go 2 template](https://golang.org/golang/proposal/blob/master/go2-language-changes.md).

- **Design Document Requirements**: If needed, design docs must be submitted to the [proposal repository](https://github.com/golang/proposal/) as `design/NNNN-shortname.md`, adhere to a [template](https://golang.org/golang/proposal/blob/master/design/TEMPLATE.md), and use Gerrit for review with 80-column wrapping and one-sentence-per-line formatting.

- **Proposal Review Process**: Weekly meetings triage proposals into columns (Incoming/Active/Likely Accept/Likely Decline/Accepted/Declined). Accepted proposals are labeled `Proposal-Accepted` and moved to implementation milestones; declined proposals are closed with optional labels (e.g., Duplicate, Infeasible).
