# Semantic Versioning 2.0.0 | Semantic Versioning

## Summary

- **Versioning Rules**: Increment `MAJOR` for backward-incompatible API changes, `MINOR` for backward-compatible functionality additions, and `PATCH` for backward-compatible bug fixes. Pre-release (`-alpha`, `-beta`) and build metadata (`+001`) are supported extensions.

- **Version Format**: MUST follow `X.Y.Z` (non-negative integers, no leading zeros), where `X` is major, `Y` minor, and `Z` patch. Precedence is determined by left-to-right comparison of identifiers, with pre-release versions having lower precedence than normal versions.

- **Constraints**: Once released, version contents MUST NOT be modified; new versions must be published instead. Major version `0.y.z` is for initial development (unstable API), while `1.0.0` defines the stable public API.
