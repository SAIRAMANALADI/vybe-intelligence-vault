# Semantic Versioning 2.0.0 | Semantic Versioning

## Summary

- **Versioning Rules**: Semantic Versioning (SemVer) uses `MAJOR.MINOR.PATCH` format where:
  - `MAJOR` increments for backward-incompatible API changes,
  - `MINOR` for backward-compatible new functionality,
  - `PATCH` for backward-compatible bug fixes.
  Pre-release (`-alpha`, `-beta`) and build metadata (`+20130313`) are extensions.

- **Precedence & Stability**: Pre-release versions have lower precedence than stable releases (e.g., `1.0.0-alpha < 1.0.0`). Major version `0.y.z` is for initial development (unstable API); `1.0.0` marks stable public API.

- **Version Format & Constraints**: Version numbers must be `X.Y.Z` (non-negative integers, no leading zeros). Once released, versions are immutable; modifications require new versions. Build metadata is ignored in precedence comparisons.
